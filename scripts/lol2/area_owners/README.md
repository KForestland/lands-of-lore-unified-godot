# Area owners

Add one entry to an area's `OWNERS` array. The registry handles attachment, mesh/collision claims, optional restore and validation; hosts keep engine services. Owners remain direct children of the host with their original names and saved keys. Resource paths are strings so this list does not build an eager owner/host/save preload cycle.

`{"script": "my_owner.gd"}` calls static `attach(host)`. Optional `attach` selects another factory; `args` appends arguments. `needs: "progression"` skips attachment while progression is absent. The L8 journey alone uses `factory: "new"` and receives its host before `add_child`.

`act2_map` calls `early` before region visibility, then `late`. The default phase is `late`; set `phase: "early"` for an owner that belongs before that boundary. Each phase follows list order, as do `owners()` results. The L8/L9 hosts have one attachment phase.

Before geometry construction, `prepare()` loads the list and rejects duplicate nonempty keys. Static `owns(face)` claims both drawing and collision; `owns_collision(face)` overrides collision. Entry `static` / `collision` arrays override method names, including `[]` to retain a legacy non-claim. L10/L9 assembly-index rules live in their list files. Host terrain, Binder, visibility, static-assembly setup and edge rules remain unchanged.

An owner's `RESTORE_ON` array enables `load` and/or `arrival`; absence means no call. `restore_order` preserves legacy load order independently of attach order; `restore_args` preserves L9 Escape's `true`. An explicit `restore_on` entry handles L13 Elevator: its GDScript parent already defines `RESTORE_ON`, so the child cannot redeclare it. Inherited constants and static methods are resolved through the script ancestry. L10 EmperorEntry and L13 Elevator reuse rendering bases but have separate quest keys and lifecycles: their key/validator/restore aliases are explicit in their list entries. All 21 existing load owners and seven arrival owners retain their schedules; the plan's 41 additional registry load calls remain off pending separate per-level gameplay proof.

For a present `KEY`, static `validate(value)` or `validate(value, quests)` runs. Five older L9 owners and the two rendering subclasses have list `key` aliases for existing keys. `validate` can select a nonstandard method (`validate_lift`), or `""` to leave state-only validation to the retained aggregate (Ankh, rather than the inherited Oil validator). Missing keys remain optional. The old aggregate validation, including state-only and nonstandard `validate_lift` checks, stays intact. All ten initial legacy host packets and Plan1's five d5 writer fixtures remain accepted; no applicable validator needed an old-save compatibility exclusion. Entry's inherited Oil validator is inapplicable to its Ankh key; the retained Ankh aggregate check still owns that validation.
